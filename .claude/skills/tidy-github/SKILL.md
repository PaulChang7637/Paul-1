# 倉庫深度整理

依下列順序執行,過程中保持小步提交:

1. **產生報告**:執行 `python3 scripts/tidy_repo.py > /tmp/report.md`,
   閱讀報告內容(INDEX.md 會同時被更新)。
2. **自動修復**:報告中列出的失效 Markdown 相對連結,找出正確目標後直接修正;
   INDEX.md 的更新直接納入提交。
3. **命名建議**:對違反命名規則的檔案(含空格、過長、與內容不符的名稱),
   用 `git mv` 提出改名方案,**先列清單徵得使用者同意再執行**,
   改名後同步修正所有引用該檔案的連結。
4. **分類與文件**:檢查 README.md 是否涵蓋所有資料夾與主要檔案;
   新增的內容要補上一句說明與相對連結。資料夾結構不合理時提出搬移建議。
5. **帳號層級**:報告中若列出缺少描述或 topics 的倉庫,
   替每個倉庫擬好一句描述與 3–6 個 topics 供使用者直接貼上
   (GitHub 倉庫頁右上 About 區塊的齒輪可編輯)。
6. **提交**:訊息格式 `chore: 整理倉庫(YYYY-MM)`,推送到目前分支。

注意:絕不在未經使用者確認的情況下刪除檔案或重新命名倉庫本身。
